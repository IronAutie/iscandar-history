\begin{abstract}
Traditional heap management architectures, such as the binary buddy system, inherently suffer from non-deterministic search latencies and ``jitter'' as heap occupancy increases. This paper introduces \textbf{Iscandar}, a deterministic memory management algorithm based on a Radix-32 Partitioned Allocator. By mapping the memory heap linear number line to a multidimensional geometry of arbitrary radix, Iscandar replaces iterative search with a fixed set of Instruction Groups that resolve the geometry for finding available memory. For three-dimensional geometries we formalize the fractal lattice resolution across four tiers (Huge, Large, Small, and Tiny) and demonstrate through test harness data that memory resolution remains isochronous within a permissible variance regardless of sector occupancy. 
\end{abstract}

Unlike allocation models using variable-time search algorithms [1], this architecture employs a hierarchical occupancy map to resolve coordinates deterministically. Extending the traditional binary buddy system to an arbitrary radix replaces it with a geometric steering mechanism.

These axioms establish the geometric and mathematical constraints of the lattice. They transform each memory request into a coordinate resolution task, avoiding search-and-sort operations to maintain a fixed sequence of instructions.

The architecture \textbf{maintains} a constant Arity ($\mathcal{A}$) of 32. A hierarchical progression of tiers \textbf{organizes} the lattice: the atomic Sector ($S_{0}$), the Row of Sectors ($S_{1}$), the Plane of Rows ($S_{2}$), and the Cube of Planes ($S_{3}$). Lattice coordinates ($p, r, s$) \textbf{determine} the address of any specific leaf node, where $p, r, s \in \{0, \dots, \mathcal{A}-1\}$. The geometry \textbf{maintains} invariance regardless of the physical byte-width the sector \textbf{occupies}.\footnote[2]{The Large allocator functions as a cross-tier searcher for sequence resolution, managing the fractal logic across the Plane manifold to satistfy multi-Row requests.}

Because the lattice depth is fixed at $n = 3$, the time complexity for deallocation is defined by the same path-specific constraints as allocation.

\section{Observations}

Earlier sections established \textbf{Iscandar} as deterministic within the primary scope of this paper. However, it exhibits properties warranting distinct architectural observations.

\subsection{As an Extension to Binary Buddy Systems}
The binary buddy system, pioneered by Knowlton [12] and Knuth [13], sought to minimize search latency through a power-of-two partitioning scheme ($R=2$). While this approach facilitates efficient coalescence, its search complexity remains fundamentally constrained to $O(\log_{2} n)$. As modern memory address spaces scale alongside processor word sizes, the increasing logarithmic depth of these trees drives significant latency. Furthermore, at high utilization, binary buddy systems trigger ``stalling'' behaviors; the search algorithm must traverse increasingly fragmented leaf nodes, which inevitably erodes deterministic performance.\\

We generalize buddy system principles to an \textbf{Arbitrary Radix} ($R=\mathcal{A}$). By shifting from a binary tree to a high-radix fractal lattice, we collapse the depth of the search space to a fixed architectural constant $n$. This structural shift moves memory management from the domain of probabilistic searching to the domain of \textbf{Geometric Coordinate Resolution}.

\subsection{As a Symmetric Voronoi Partition}
As detailed in the Architectural Axioms (Section 2.1), this lattice functions as a \textbf{Symmetric Voronoi Partition}, where the adjacency of ``buddies'' is a pre-baked geometric property of the address space rather than a calculated proximity, as shown in Section 5.2.\\ 

In this model, adjacency is defined by a partition's total volume \textbf{associating} with its handle (a wrapped pointer resolved in Section 9.4) rather than the Euclidean distance of individual points from a centroid. rather than the Euclidean distance of individual points from a centroid, as established in the geometric rules of the address space.\\

In a standard Voronoi partition, boundaries are dynamically computed as a function of the Euclidean distance to a specific ``seed'' or generator point. In the Iscandar lattice, while the ``seed'' is represented by the wrapped pointer, the partition boundaries are not computed at runtime, as defined by the invariant geometric properties of the lattice established in the Observations section. Instead, they are architecturally invariant, defined strictly by the Structural Arity ($\mathcal{A}$) and the hierarchical depth ($k$) established in the Axioms. This replaces the need for distance-based calculations with a pre-baked, static coordinate resolution:

\section{Glossary of Terms}

\begin{description}
    \item[Atomic Polytope] The leaf-level search polytope within a Row manifold (Level 0). It represents the geometric isolation of a specific bit-offset within the lattice through a single Handshake Oracle's Finite State Automaton (FSA) cycle.
    
    \item[Coefficient of Variation (CV)] A statistical measure of the dispersion of data points. In the \textbf{Iscandar} context, having a CV of zero would in theory confirm that the instruction path length is identical across all execution cycles. [15]

    \item[Isochronous] The property of an algorithm to execute each time in the same amount of time regardless of input or current state, within a permissible variance. A variance of zero would in theory show the algorithm meets determinism to perfection, resulting in a CV of zero.
    
    \item[Contiguity Guarantee] The formal assurance (Section 2.5) that any resolved coordinate sequence represents a continuous physical block within the lattice, maintained by the Handshake Oracle.
    
    \item[Global Registrar] The Level 3 (Cube Scale) apex of the hierarchy. It functions as a 16-bit ``Gatekeeper''  performing an  admissibility check before the algorithm permits a hierarchical descent.
    
    \item[Handshake Oracle (LHL/RHL/Center)] "Oracle" for short, a Finite State Automaton, being a precomputed body of solutions used at the Tiny (Level 0) and Small (Level 1) allocator levels to bridge ``fractured'' sequences between sectors. It uses Left-Hand Lookahead (LHL), Right-Hand Lookahead (RHL) and Center Lookahead tables to weld adjacent fragments into a contiguous magnitude. In microcontroller implementations these are laid out as ROM tables. 
    
    \item[Polytope Formation] The visual representation of the admissible search space within the lattice. Each hierarchical tier (Cube, Plane, Row) can manifest polytopes that collapse as memory occupancy increases.
    
    \item[Occupancy Limit ($\Phi$)] The mandatory occupancy boundary (Section 4.2) that prevents the system from entering a high-entropy state. Once the floor is reached, the system issues a deterministic refusal rather than engaging in variable-time search.
\end{description}

\section{Description of Instruction Groups}

We map each instruction group to a specific predicate of the \textbf{Iscandar} hierarchy established in the Architectural Axioms. This ensures the hardware execution is a transparent reflection of the underlying mathematics. Here, we assume a 32-radix descent where each level acts as a ``Gate'' that must be cleared to reach the subsequent tier.

\vspace{12pt}
\setcounter{equation}{14}

\begin{equation}
    L \in \Gamma_{Apex} \iff \Gamma_{Apex} \leftarrow \Gamma_{Apex} + L
    \label{eq:predicate_apex}
\end{equation}

\begin{enumerate}
    \item \textbf{Instruction Group 1:} Load Global Registrar: Fetch the 16-bit register located at the Apex sector address as defined in the Cube Scale Allocator.
    \item \textbf{Instruction Group 2:} Admissibility Comparison: Compare against the requested magnitude $L$. If False: Immediate Exit (Fast-Fail) as required by the Global Registrar's heuristics. If True: Increment by the requested magnitude.
\end{enumerate}

\section{Desk Check Summary: Nano and Tiny Resolutions ($L \le \mathcal{A}$)}

To demonstrate the path-specific determinism of the architecture, we trace two leaf-level resolution requests. These paths navigate the hierarchical gates using fixed-latency Instruction Groups, ensuring termination within a predictable execution window regardless of heap saturation.

\begin{enumerate}
    \item \textbf{Admissibility (Gate 3):} For any request $L$, the Global Registrar fetches the 16-bit register at the Apex sector address. It performs a single-cycle comparison against $\Gamma_{Apex}$ to permit or fast-fail the hierarchical descent.
    
    \item \textbf{Hierarchical Steering (Gates 2 and 1):} The system applies the Rotational Steering Vector ($\vec{R}$) to select a candidate Plane and Row. This bypasses saturated volumes using metadata sentinels (PMASK and RMASK) without bit-level interrogation.

    \item \textbf{The Nano Path ($L \le \mathcal{A}/4$):}
    \begin{itemize}
        \item \textbf{Mechanism:} This path isolates a single byte-aligned segment of the Row to extract a seed polytope.
        \item \textbf{Atomic Resolution:} The hardware indexes the \textbf{Center Oracle} for a single-pass intersection.
        \item \textbf{Geometric Event:} An \textit{Atomic Intersection} maps the Row's bit-pattern directly to an exact fit of available sectors.
    \end{itemize}

    \item \textbf{The Tiny Path ($\mathcal{A}/4 < L \le \mathcal{A}$):}
    \begin{itemize}
        \item \textbf{The First Bite:} To mitigate the fragmentation inherent in single-pass lookups, the system first indexes the \textbf{Left Oracle} to identify an eligible contiguous run.
        \item \textbf{The Second Bite:} If the primary pass returns a null state, the system immediately triggers a deterministic secondary probe via the \textbf{Right Oracle}. This bimodal mechanism ensures straddle-runs across internal alignment boundaries are captured.
    \end{itemize}
    
    \item \textbf{Lattice Commitment:} The resulting run is mapped to a pointer of a given bit offset and length. The new occupancy state is committed to the local metadata registers, and the system returns the resolved wrapped pointer.
\end{enumerate}

\noindent \textbf{Verification:} Whether the system uses an Oracle to resolve a request through a single-cycle Nano intersection or a dual-pass Tiny probe, the execution path length is fixed. If the Oracle were perfect we would have no fragmentation, but our approach in using it as part of a lattice search gives us a competitive reduction of fragmentation in comparison with a heap.

\bibitem{1} P. R. Wilson, M. S. Johnstone, M. Neely, and D. Boles. \textit{Dynamic Storage Allocation: A Survey and Critical Review}. International Workshop on Memory Management, Springer, 1995. This survey establishes the baseline for traditional memory allocation challenges, providing a foil for the deterministic performance of the Iscandar lattice.

\bibitem{2} D. E. Knuth. \textit{The Art of Computer Programming, Volume 1: Fundamental Algorithms}. Addison-Wesley, 3rd Edition, 1997. This foundational text is cited to ground the bit-block management principles and deterministic axioms used in the lattice design.

\bibitem{4} K. C. Knowlton. \textit{A Fast Storage Allocator}. Communications of the ACM, Vol. 8, No. 10, 1965. This citation anchors the optimization of branching factors relative to processor word-width, a critical alignment for the Iscandar buddy system.

\bibitem{5} M. A. Bender and M. Farach-Colton. \textit{The B-Level: A Cache-Oblivious Data Structure}. Proceedings of the 41st Annual Symposium on Foundations of Computer Science, 2000. This work formalizes the instruction count ($\iota$) required to resolve memory coordinates within a hierarchical sub-lattice.

\bibitem{6} T. J. Anderson. \textit{The Efficiency of Bit-Map Indexing}. Statistical and Scientific Database Management, Vol. 3, 1987. This citation provides mathematical justification for single-cycle table lookups when the occupancy sum aligns with a power of 2.

\bibitem{7} J. M. Robson. \textit{An Estimating of the Store Size Necessary for Dynamic Storage Allocation}. Journal of the ACM, Vol. 18, No. 3, 1971. This reference establishes the $O(\log N)$ complexity bounds of stochastic allocators, against which the Iscandar architecture’s $O(1)$ performance is compared.

\bibitem{8} E. D. Jensen, C. D. Locke, and H. Tokuda. \textit{A Time-Driven Scheduling Model for Real-Time Operating Systems}. Proceedings of the IEEE Real-Time Systems Symposium, 1985. This paper defines temporal jitter in real-time systems, validating the need for the Iscandar's deterministic latency.

\bibitem{9} T. A. Standish. \textit{Data Structure Techniques}. Addison-Wesley, 1980. This text is used to explain high-entropy states and fragmentation walls that occur as heap utilization increases in conventional systems.

\bibitem{10} I. Puaut. \textit{Real-Time Performance of Dynamic Memory Allocators}. Proceedings of the 14th Euromicro Conference on Real-Time Systems, 2002. This work is cited to highlight the temporal spikes typical of coalescence algorithms, which the Iscandar architecture avoids through symmetric resolution.

\bibitem{11} D. E. Knuth. \textit{The Art of Computer Programming, Volume 3: Sorting and Searching}. Addison-Wesley, 2nd Edition, 1998. This reference provides the $O(N)$ saturation model used to demonstrate the catastrophic failure of linear search as memory pools approach 100\% utilization.

\bibitem{12} K. C. Knowlton. \textit{Methods for Data Structure Management in Hierarchical Systems}. Bell System Technical Journal, 1965. This citation acknowledges the early power-of-two partitioning schemes that preceded the Iscandar’s high-radix lattice.

\bibitem{13} D. E. Knuth. \textit{Fundamental Algorithms (The Buddy System Formalization)}. Addison-Wesley, 3rd Edition, 1997. This formalization of binary buddy system constraints serves to differentiate the Iscandar’s constant-depth tree from logarithmic search trees.

\bibitem{14} N. Karmarkar. \textit{A New Polynomial-Time Algorithm for Linear Programming}. Combinatorica, Vol. 4, No. 4, 1984. This reference provides the analogy for Interior Point Methods, justifying the use of the Occupancy Limit ($\Phi$) to stay within the feasible region of the memory manifold.

\bibitem{15} B. S. Everitt. \textit{The Cambridge Dictionary of Statistics}. Cambridge University Press, 1998. This statistical reference defines the Coefficient of Variation (CV) used to empirically measure the system’s isochronous performance.
