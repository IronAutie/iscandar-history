\section{Introduction}

Unlike allocation models using variable-time search algorithms [1], this architecture employs a hierarchical occupancy map to resolve coordinates deterministically. Extending the traditional binary buddy system to an arbitrary radix replaces it with a geometric steering mechanism.

\section{Architectural Axioms}

These axioms establish the geometric and mathematical constraints of the lattice. They transform each memory request into a coordinate resolution task, avoiding search-and-sort operations to maintain an instruction determinism of exactly 13 steps.

\subsection{Axiom I: The State Map (L) and Structural Arity ($\mathcal{A})$}

For modeling and testing purposes this paper demonstrates an $n$-level lattice $L$ of fixed depth ($n=3$) \textbf{defining} a total memory space. The architecture \textbf{maintains} a constant Arity ($\mathcal{A}$) of 32. A hierarchical progression of tiers \textbf{organizes} the lattice: the atomic Sector ($S_{0}$), the Row of Sectors ($S_{1}$), the Plane of Rows ($S_{2}$), and the Cube of Planes ($S_{3}$). Lattice coordinates ($p, r, s$) \textbf{determine} the address of any specific leaf node, where $p, r, s \in \{0, \dots, \mathcal{A}-1\}$. The geometry \textbf{maintains} invariance regardless of the physical byte-width the sector \textbf{occupies}.\footnote[2]{The Large allocator functions as a cross-tier searcher for sequence resolution, managing the fractal logic across the Plane manifold to satistfy multi-Row requests.}

\subsection{Axiom II: Hierarchical Occupancy Counters ($\Gamma$)}

Discrete occupancy counts ($\Gamma$) at every tier \textbf{enable} constant-time steering. Following bit-block representation principles [2], these counters \textbf{generate} a real-time density map of the lattice:

\begin{itemize}
    \item \textbf{Level 1 (Row):} $\Gamma_{1} = \sum_{i=0}^{\mathcal{A}-1} \Gamma_{0,i}$
    \item \textbf{Level 2 (Plane):} $\Gamma_{2} = \sum_{j=0}^{\mathcal{A}-1} \Gamma_{1,j}$
    \item \textbf{Level 3 (Cube):} $\Gamma_{3} = \sum_{k=0}^{\mathcal{A}-1} \Gamma_{2,k}$
\end{itemize}

This hierarchical summation lets the Global Registrar to \textbf{execute} an admissibility check in a single instruction cycle, \textbf{fulfilling} the fast-fail condition established in the audit.

\subsection{Axiom III: Discrete Enforcement of the Resilience Floor ($\Phi$)}

The Iscandar system \textbf{enforces} a mandatory occupancy boundary, the Resilience Floor ($\Phi$). Traditional allocators search for gaps as memory nears capacity; in contrast, this system \textbf{triggers} a deterministic refusal once $\Gamma_{3}$ reaches the $\Phi$ threshold.

\subsection{Axiom IV: Rotational Steering ($\vec{R}$)}
A rotational steering vector \textbf{balances} the lattice structure, preventing localized occupancy ``hot spots'' and maintaining the Handshake Oracle within its optimal operational tax. The instruction tax depends on the Oracle resolving a valid ``weld'' or ``gap'' within a single word-width scan of magnitude $\mathcal{A}$. To prevent high-density clusters that necessitate bit-shuffling or metadata updates, the system utilizes $\vec{R}$ to distribute entropy across the manifold [3].

\subsection{Axiom V: The Contiguity Guarantee}

Any resolved coordinate sequence \textbf{represents} a continuous physical block in the Iscandar lattice. The Level 1 LHL/RHL Handshake Oracle \textbf{enforces} this property, \textbf{validating} that the combined leading and trailing fragments across a sector-join \textbf{equal} the requested magnitude $M$ without gaps.

\section{Inductive Proof of Deterministic Resolution}

\noindent \textbf{Theorem:} A fixed-depth $\mathcal{L}$ of Arity $\mathcal{A}=32$ \textbf{establishes} deterministic resolution for operator $\Omega$.

\subsection{The Complexity Proof}

The $\mathcal{L}$ \textbf{maps} its branching factor to the processor word-width to \textbf{optimize} the classical buddy system search [3]. Let $\mathcal{L}_{n}$ \textbf{designate} a sub-lattice of level $n$, where resolution time $T(\mathcal{L}_{n})$ \textbf{represents} the total instruction count ($\iota$) required to \textbf{resolve} a memory coordinate. Resolution time $T(\mathcal{L}_{n})$ \textbf{represents} the instruction count ($\iota$) for \textbf{resolving} a memory coordinate in a level-$n$ sub-lattice [4]. \\

\begin{enumerate}
    \item \textbf{Base Case ($n = 1$):} At the Row level ($\mathcal{L}_{1}$), a hardware bit-scan primitive \textbf{resolves} a free sector; this operation \textbf{maintains} atomicity on 32-bit architectures.
    \begin{equation}
        T(\mathcal{L}_{1}) = I_{base}
    \end{equation}

    \item \textbf{Inductive Step:} Given the invariant that resolution time for a level-$k$ structure is $T(\mathcal{L}_{k}) = kI_{base}$, resolving a request at level $k+1$ (e.g., the Plane level) \textbf{requires}:
    \begin{itemize}
        \item The occupancy sum $\Gamma_{k+1}$ is \textbf{evaluated} via bitmask comparison to \textbf{select} a viable Level-$k$ child. When $\mathcal{A}$ \textbf{aligns} with a power of 2, this lookup and steering operation \textbf{consumes} a single table lookup [4].
        \item The resolution operation \textbf{descends} to the level-$k$ $\mathcal{L}$ identified by the steering vector from the Oracle.
        \item The resulting recurrence relation is:
        \begin{equation}
            T(\mathcal{L}_{k+1}) = I_{base} + T(\mathcal{L}_k) = I_{base} + kI_{base} = (k+1)I_{base}
        \end{equation}
        \item \textbf{Termination Constraint:} The recursion \textbf{terminates} at $\mathcal{L}_{1}$, where the hardware bit-scan \textbf{yields} the final effective address offset.
    \end{itemize}
\end{enumerate}


\subsection{Conclusion of Determinism}
By induction, the resolution time for any $n$-level $\mathcal{L}$ structure is strictly $nI_{base}$. While standard stochastic allocators exhibit execution times as a function of free-block count ($N$)—typically yielding $O(\log N)$ or worse in fragmented states [5]—the Iscandar architecture \textbf{collapses} this complexity. $n$ as a constant \textbf{enforces} deterministic latency of resolution regardless of heap saturation.\\

In the Iscandar model, $n$ is an architectural constant (e.g., $n = 3$); so total execution time is:
\begin{equation}
    T_{total} = 3I_{base}
\end{equation}

This result confirms that for a Cube of $\mathcal{A}^k$ Sectors, the time required to resolve an address is invariant. This performance is maintained provided the system stays in the operational domain of the Resilience Floor ($\Phi$). By trading spatial capacity for temporal certainty, the architecture \textbf{eliminates} the ``temporal jitter'' that characterizes non-deterministic real-time systems. [5]

\subsection{Temporal Consistency and Boundary Management}
To \textbf{preclude} latency variability during boundary-straddling, Iscandar \textbf{utilizes} a computational handshake or ``Oracle,'' a precomputed resolution-path for non-aligned straddle cases, \textbf{ensuring} the instruction count for a $\mathcal{A}$-sector block remains \textbf{isochronous} regardless of its alignment relative to the Tier-1 registers. By \textbf{eliminating} the alignment-check penalty, the architecture \textbf{preserves} a deterministic execution window across the entire addressable space.\\

Here we describe the ``Factory'' math used to pre-calculate the Oracle tables, transforming a search problem into a static retrieval of pre-verified geometric facts.

\subsubsection{Generating the Boundary Tables (RHL/LHL)}
The boundary tables are 1D vectors that map every possible bit-permutation of a Guard Shard to its boundary potential.
\begin{itemize}
    \item \textbf{Right-Hand Lookahead (RHL):} For any shard state $S$, the table stores the starting index of the longest contiguous zero-run terminating at the right-hand boundary. If the terminal bit is \textbf{1}, the value is \textbf{Null}.
    \item \textbf{Left-Hand Lookahead (LHL):} Maps the shard state to the final bit position of the zero-run starting from the left-hand boundary. If the initial bit is \textbf{1}, the value is \textbf{Null}.
    \item \textbf{Math:} These are pre-calculated \textit{Suffix/Prefix Automata} that eliminate runtime scanning \cite{stringology}.
\end{itemize}

\subsubsection{Generating the Core Oracle (2D Matrix)}
The Core Shard utilizes a 2D matrix ($2^{\mathcal{A}/4} \times \mathcal{A}/4$) to resolve internal gaps.
\begin{itemize}
    \item \textbf{Mechanism:} Exhaustive enumeration of all $2^{\mathcal{A}/4}$ bit-patterns against all possible length requests within the core.
    \item \textbf{Math:} Each cell $(i, j)$ is filled using a windowed zero-run algorithm. This transforms the shard into a lookup-based \textit{Finite State Transducer} \cite{stringology}.
\end{itemize}

\subsubsection{The Cube Case (The Boolean Primitive)}
The ``Cube Case'' represents the \textbf{Ultimate Degeneracy}. It is the boolean truth for the entire $\mathcal{A}^k$ bitspace.
\begin{itemize}
    \item \textbf{Scale:} A single bit of metadata representing the occupancy of the entire $\mathcal{A}^k$ volume.
    \item \textbf{Boolean Law:} 
        \begin{itemize}
            \item \textbf{0 (Open):} The entire volume is zero.
            \item \textbf{1 (Closed):} Any bit within the volume is one.
        \end{itemize}
    \item \textbf{Math:} This represents the collapse of a high-dimensional state space into a \textit{Degenerate Polytope}, providing the structural filler for Huge Case construction with $O(1)$ verification \cite{combinatorial}.
\end{itemize}



\section{Deterministic Coalescence and the Resilience Floor}
Maintaining temporal determinism in a dynamic environment \textbf{requires} a deallocation process (coalescence) \textbf{mirroring} the efficiency of the allocation logic. Operational stability of the iscandar lattice uses discrete enforcement of the Resilience Floor ($\Phi$), \textbf{precluding} the high-entropy states typically associated with stochastic fragmentation [5].

\subsection{Symmetric Coalescence Mechanics}
In the iscandar architecture, coalescence is not a variable-time search for adjacent free blocks, but a \textbf{deterministic state update}. Whether the Oracle \textbf{descends} to clear a bit-position or \textbf{propagates} the release upward through the hierarchy, the operation \textbf{remains isochronous}. Because the bit-address of any Sector ($S_{0}$) is a fixed function of its coordinates, the update to the occupancy counters ($\Gamma$) \textbf{consumes} the same instruction count ($I_{base}$) as the initial resolution.

\begin{enumerate}
    \item The atomic leaf node state $\Gamma_{0}$ is \textbf{toggled} to $0$ (Available).
    \item The change \textbf{propagates} immediately to the parent Row counter ($\Gamma_{1}$).
    \item The Level-2 (Plane) and Level-3 (Cube) counters are \textbf{updated} through integer subtraction.
\end{enumerate}

Because the lattice depth is fixed at $n=3$, time complexity for allocation are identical to deallocation ($3I_{base}$). This symmetry \textbf{ensures} that system overhead remains constant regardless of memory ``churn,'' \textbf{eliminating} the temporal spikes typically made by coalescing algorithms [6].

\subsection{Operational Enforcement of $\Omega$}
The Resilience Floor ($\Phi$) \textbf{serves} as the authoritative boundary of the system’s operational domain. While traditional allocators attempt to satisfy requests until the address space is 100\% utilized---leading to $O(N)$ search patterns as fragmentation increases [7]---the iscandar lattice \textbf{utilizes} the $\Gamma_{3}$ counter as a deterministic ``circuit breaker.''\\

The decision logic for the Resolution Operator ($\Omega$) is:
\begin{equation}
\Omega(\text{request}) = 
\begin{cases} 
\text{Resolve}(p, r, s) & \text{if } \Gamma_{3} < K \\
\text{Refuse}(\text{Constant Time}) & \text{if } \Gamma_{3} \geq K 
\end{cases}
\end{equation}
where $K$ is the sector threshold at which the Resilience Floor is triggered ($K = \mathcal{A}^k \times (1 - \Phi)$)

\subsection{Summary of Empirical Performance}

This enforcement mechanism ensures the system never enters the ``fragmentation trap.'' By refusing to allocate beyond the floor ($\Phi$), \textbf{iscandar} guarantees that the internal density of the $\mathcal{A}$-way branching structures never reaches a threshold where bit-mask steering degrades to a linear probe.

\section{Observations}

Earlier sections established Iscandar as deterministic within the primary scope of this paper. However, it exhibits properties warranting distinct architectural observations.

\subsection{As an Extension to Binary Buddy Systems}
The binary buddy system, pioneered by Knowlton [8] and Knuth [9], sought to minimize search latency through a power-of-two partitioning scheme ($R=2$). While this approach facilitates efficient coalescence, its search complexity remains fundamentally constrained to $O(\log_{2} n)$. As modern memory address spaces scale alongside processor word sizes, the increasing logarithmic depth of these trees drives significant latency. Furthermore, at high utilization, binary buddy systems trigger ``stalling'' behaviors; the search algorithm must traverse increasingly fragmented leaf nodes, which inevitably erodes deterministic performance.\\

We generalize buddy system principles to an \textbf{Arbitrary Radix} ($R=\mathcal{A}$). By shifting from a binary tree to a high-radix fractal lattice, we collapse the depth of the search space to a fixed architectural constant $n$. This structural shift moves memory management from the domain of probabilistic searching to the domain of \textbf{Geometric Coordinate Resolution}.

\subsection{As a Symmetric Voronoi Partition}
As detailed in the appendices, this lattice functions as a \textbf{Symmetric Voronoi Partition}, where the adjacency of ``buddies'' is a pre-baked geometric property of the address space rather than a calculated proximity. In this model, adjacency is defined by a partition's total volume \textbf{associating} with its handle (a wrapped pointer), rather than the Euclidean distance of individual points from a centroid (e.g., the proximity of residences to a central post office).

\subsection{As Linear Programming}

The operational stability of the system is maintained via an \textbf{Interior Point Method}---analogous to projective transformations used in Karmarkar’s algorithm [10]. By enforcing a \textbf{Resilience Floor} ($\Phi$), we \textbf{ensure} the resolution path avoids ``edges'' of the feasible region (the fragmentation trap). Here, the allocator does not merely manage space; it \textbf{navigates} a high-dimensional manifold where the floor serves as a protective barrier against non-deterministic search behaviors.

\subsection{Amortized Performance: Constant Time}
The Iscandar architecture utilizes a \textit{Seamless Sack} model that achieves amortized constant time for memory operations through a Next-Fit Circular Cursor mechanism.

\begin{itemize}
    \item \textbf{Mechanism:} The cursor maintains forward momentum across the $\mathcal{A}^k$-sector manifold. By never re-scanning fragmented entropy within a single ``lap,'' the system distributes the metabolic cost of search across its entire operational lifecycle.
    \item \textbf{Forward-Pressure Principle:} The system treats fragmentation as a transient spatial cost. It offsets the latency of filtering fragmented sectors by performing high-efficiency, contiguous allocations in reclaimed or vacant regions.
\end{itemize}

\subsection{Performance Bound: Sub-Linear Determinism}
The architecture maintains determinism through hierarchical skip-logic at intermediate levels. This mechanism constrains the worst-case search complexity to the $k$-th root of the total lattice volume, where $k$ represents the depth of the fractal hierarchy.

\begin{itemize}
    \item \textbf{Mechanism: Dimensional Collapse.} The architecture maps the 1D address space to a $k$-dimensional manifold ($\mathcal{A}^k$). Metadata sentinels at the Plane and Row levels enable the search engine to bypass saturated volumes without bit-level interrogation.
    \item \textbf{Logic for Cubic Architecture:}
    \begin{enumerate}
        \item \textbf{Plane-Skip:} Evaluates $\mathcal{A}^2$-sector manifolds; the engine executes an $O(1)$ leap if free space is less than the request size.
        \item \textbf{Row-Skip:} Evaluates $\mathcal{A}$-sector rows; the engine executes an $O(1)$ leap if row density proves prohibitive.
        \item \textbf{Bit-Scan:} The engine restricts final verification to a single bit-vector of magnitude $\mathcal{A}$.
    \end{enumerate}
    \item \textbf{Deterministic Ceiling:} For a lattice of volume $N = \mathcal{A}^k$, the architecture caps the maximum investigation path at $k \times \mathcal{A}$, limiting the worst-case cost to $k \times \mathcal{A}$ operations.
\end{itemize}

\subsection{As Supporting Six Sigma Design}
As detailed in the appendices, the compactness of the iscandar kernel enables \textbf{complete path coverage testing} that operates in tandem with the previously established formal methods. The convergence of exhaustive path verification and formal proofs provides the necessary rigor to certify the algorithm as a \textbf{fault-tolerant} memory system, suitable for high-reliability applications.

\subsection{Scalability via Depth Extension}
The \textbf{iscandar} architecture scales by increasing the lattice depth up to two additional levels. Because the resolution time is a linear function of depth ($k \times I_{base}$), extending the lattice to $k = 4$ or $k = 5$ provides a massive increase in addressable memory volume while maintaining a strictly deterministic and predictable execution profile.

\subsection{As Supporting Parallel Execution}

The architecture allows for the distribution of the management load through parallel instantiation. Lesser structures can be managed by hardware subroutines to distribute the processing requirements across multiple units. These parallel hardware components can also supervise local memory independently, communicating management data upward through the hierarchy only as required.

\section{Conclusion}
The \textbf{iscandar} architecture demonstrates that the non-deterministic latency inherent in traditional memory management is a byproduct of stochastic search methodologies rather than a physical necessity. Replacing variable-depth search algorithms with a fixed-depth, $\mathcal{A}$-radix fractal lattice establishes deterministic execution.\\

\section{Glossary of Terms}

\begin{description}
    \item[Atomic Polytope] The leaf-level search polytope within a Row manifold (Level 0). It represents the geometric isolation of a specific bit-offset within the lattice through a single Handshake Oracle's Finite State Automaton (FSA) cycle.
    
    \item[Coefficient of Variation (CV)] A statistical measure of the dispersion of data points. In the Iscandar context, a CV of zero confirms that the instruction path length is identical across all execution cycles, proving absolute determinism. [7]
    
    \item[Contiguity Guarantee] The formal assurance (Section 2.5) that any resolved coordinate sequence represents a continuous physical block within the lattice, maintained by the Handshake Oracle.
    
    \item[Fixed Instruction Tax ($K=13$)] The invariant number of macro-instructions required to resolve any memory request, regardless of request size or the current memory occupancy.
    
    \item[Global Registrar] The Level 4 (Cube Scale) apex of the hierarchy. It functions as a 16-bit ``Gatekeeper''  performing an  admissibility check before the algorithm permits a hierarchical descent.
    
    \item[Handshake Oracle (LHL/RHL/Center)] A Finite State Automaton, being a precomputed body of solutions used at the Tiny (Level 0) and Small (Level 1) allocator levels to bridge ``fractured'' sequences between sectors. It utilizes Left-Hand Lookahead (LHL), Right-Hand Lookahead (RHL) and Center Lookahead constants to weld disparate fragments into a contiguous magnitude. In microcontroller implementations these are laid out as ROM tables. 
    
    \item[Polytope Formation] The visual representation of the admissible search space within the lattice. Each hierarchical tier (Cube, Plane, Row) can manifest polytopes that collapse as memory occupancy increases.
    
    \item[Resilience Floor ($\Phi$)] The mandatory occupancy boundary (Section 4.2) that prevents the system from entering a high-entropy state. Once the floor is reached, the system issues a deterministic refusal rather than engaging in variable-time search.
\end{description}

\section*{Appendix C: The $K=13$ Detailed Description of Instructions}

To perform an ``honest'' audit for the monograph, we must map each of the 13 macro-instructions ($K=13$) to the specific discrete predicates of the iscandar hierarchy established in the Architectural Axioms. This ensures the hardware execution is a transparent reflection of the underlying mathematics. The audit assumes a 32-radix descent where each level acts as a ``Gate'' that must be cleared to reach the subsequent tier.

\subsection{Phase I: The Admissibility Gate (Level 3)}
\textbf{Predicate:} $M \in \Gamma_{Apex} \iff \Gamma_{Apex} \leftarrow \Gamma_{Apex} + M$

\begin{enumerate}
    \item \textbf{Instruction 1:} Load Global Registrar: Fetch the 16-bit register located at the Apex sector address as defined in the Cube Scale Allocator.
    \item \textbf{Instruction 2:} Admissibility Comparison: Compare against the requested magnitude $M$. If False: Immediate Exit (Fast-Fail) as required by the Global Registrar's heuristics. If True: Increment by the requested magnitude.
\end{enumerate}

\subsection{Phase II: The Plane-Level Resolution (Level 2)}
\textbf{Predicate:} $P_{Plane} \iff \sum_{i \in Plane} (Row [Inclusion]) \ge M$ 

\begin{enumerate}
    \setcounter{enumi}{2}
    \item \textbf{Instruction 3:} Index Plane Metadata: Using the address bits, index into the 32-radix plane metadata table.
    \item \textbf{Instruction 4:} Load Row-Summary: Fetch the 15-bit metadata for the target plane summarizing the 32 constituent rows as established in Axiom II.
    \item \textbf{Instruction 5:} Candidate Selection: Evaluate the plane-state to identify the first row-sequence that satisfies the weld.
    \item \textbf{Instruction 6:} Heuristic Branch/Scan: Evaluate the 32-radix plane metadata scan to confirm the steering vector.
\end{enumerate}

\subsection{Phase III: The Row-Level Weld (Level 1)}
\textbf{Predicate:} $Weld \iff RHL(Row_n) + Intermediates + LHL(Row_{n+m}) \ge M$ 

\begin{enumerate}
    \setcounter{enumi}{6}
    \item \textbf{Instruction 7:} Leading Fragment Access (RHL): Perform a Look-Up Table (LUT) lookup on the starting row's tail.
    \item \textbf{Instruction 8:} Trailing Fragment Access (LHL): Perform a LUT lookup on the final row's head.
    \item \textbf{Instruction 9:} Scalar Summation: Add Lead + Intermediates + Trail, maintaining the Contiguity Guarantee.
    \item \textbf{Instruction 10:} Weld Validation: Compare the result against $M$ to finalize the inter-row continuity.
\end{enumerate}

\subsection{Phase IV: The Bit-Lattice Isolation (Level 0)}
\textbf{Predicate:} $P_{Tiny} \iff \sum_{i=start}^{end} \neg b_i = M$ 

\begin{enumerate}
    \setcounter{enumi}{10}
    \item \textbf{Instruction 11:} Center LUT Index: Access the bit-occupancy table for the target sector.
    \item \textbf{Instruction 12:} Triangle Projection: Map the LUT result to the physical bit-offset, resolving the Atomic Polytope within the Row manifold.
    \item \textbf{Instruction 13:} Commitment/Return: Write the new occupancy to the 15-bit metadata and return the start address $S$.
\end{enumerate}
