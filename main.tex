\section{Introduction to \textbf{Iscandar}}

Unlike allocation models using variable-time search algorithms [1], this architecture employs a hierarchical occupancy map to resolve coordinates deterministically. Extending the traditional binary buddy system to an arbitrary radix replaces it with a geometric steering mechanism.

\section{Architectural Axioms}

These axioms establish the geometric and mathematical constraints of the lattice. They transform each memory request into a coordinate resolution task, avoiding search-and-sort operations to maintain a fixed sequence of instructions.

\subsection{Axiom I: The State Map (L) and Structural Arity ($\mathcal{A})$}

For modeling and testing purposes this paper demonstrates an $k$-level lattice $L$ of fixed depth ($n=3$) \textbf{defining} a total memory space. The architecture \textbf{maintains} a constant Arity ($\mathcal{A}$) of 32. A hierarchical progression of tiers \textbf{organizes} the lattice: the atomic Sector ($S_{0}$), the Row of Sectors ($S_{1}$), the Plane of Rows ($S_{2}$), and the Cube of Planes ($S_{3}$). Lattice coordinates ($p, r, s$) \textbf{determine} the address of any specific leaf node, where $p, r, s \in \{0, \dots, \mathcal{A}-1\}$. The geometry \textbf{maintains} invariance regardless of the physical byte-width the sector \textbf{occupies}.\footnote[2]{The Large allocator functions as a cross-tier searcher for sequence resolution, managing the fractal logic across the Plane manifold to satistfy multi-Row requests.}

\subsection{Axiom II: Hierarchical Occupancy Counters ($\Gamma$)}

Discrete occupancy counts ($\Gamma$) at every tier \textbf{enable} constant-time steering. Following bit-block representation principles [2], these counters \textbf{generate} a real-time density map of the lattice:

\begin{align}
    \text{Level 1 (Row):} \quad \Gamma_{1} &= \sum_{i=0}^{\mathcal{A}-1} \Gamma_{0,i} \label{eq:gamma1} \\
    \text{Level 2 (Plane):} \quad \Gamma_{2} &= \sum_{j=0}^{\mathcal{A}-1} \Gamma_{1,j} \label{eq:gamma2} \\
    \text{Level 3 (Cube):} \quad \Gamma_{3} &= \sum_{k=0}^{\mathcal{A}-1} \Gamma_{2,k} \label{eq:gamma3}
\end{align}

This hierarchical summation lets a Global Registrar at the Cube level \textbf{execute} an admissibility check in a single instruction cycle, \textbf{imposing} a fast-fail condition.

\subsection{Axiom III: Enforcing an Occupancy Limit ($\Phi$)}

The \textbf{Iscandar} system \textbf{enforces} a mandatory occupancy boundary, the Occupancy Limit ($\Phi$). Traditional allocators search for gaps as memory nears capacity; in contrast, this system \textbf{triggers} a deterministic refusal once $\Gamma_{3}$ reaches the $\Phi$ threshold based on the present occupancy request.

\subsection{Axiom IV: Rotational Steering ($\vec{R}$)}
A rotational steering vector \textbf{balances} the lattice structure, preventing localized occupancy ``hot spots''. To prevent high-density clusters that necessitate bit-shuffling or metadata updates, the system utilizes $\vec{R}$ to distribute entropy across the manifold [3].

\subsection{Axiom V: The Contiguity Guarantee}

Any resolved coordinate sequence \textbf{represents} a continuous physical block in the \textbf{Iscandar} lattice. An Oracle in the form of look-up tables \textbf{validates} that the combined leading and trailing fragments across a sector-join \textbf{equal} the requested magnitude $M$ without gaps.

\section{Inductive Proof of Deterministic Resolution}

\noindent \textbf{Theorem:} A fixed-depth $\mathcal{L}$ of Arity $\mathcal{A}=32$ \textbf{establishes} deterministic resolution for operator $\Omega$.

\subsection{The Complexity Proof}

The $\mathcal{L}$ \textbf{maps} its branching factor to the processor word-width to \textbf{optimize} the classical buddy system search [4]. Let $\mathcal{L}_{n}$ \textbf{designate} a sub-lattice of level $n$, where resolution time $T(\mathcal{L}_{n})$ \textbf{represents} the total instruction count ($\iota$) required to \textbf{resolve} a memory coordinate. Resolution time $T(\mathcal{L}_{n})$ \textbf{represents} the instruction count ($\iota$) for \textbf{resolving} a memory coordinate in a level-$n$ sub-lattice [5]. \\

\begin{enumerate}
    \item \textbf{Base Case ($n = 1$):} At the Row level ($L_1$), a pre-calculated \textbf{Instruction Group mapping} resolves a free sector via a static Look-Up Table. This operation maintains atomicity by collapsing the resolution into a single-cycle, table-driven state transition.
    \begin{equation}
        T(\mathcal{L}_{1}) = I_{base}
    \end{equation}

    \item \textbf{Inductive Step:} Given the invariant that resolution time for a level-$k$ structure is $T(\mathcal{L}_{k}) = kI_{base}$, resolving a request at level $k+1$ (e.g., the Plane level) \textbf{requires}:
    \begin{itemize}
        \item The occupancy sum $\Gamma_{k+1}$ is \textbf{evaluated} via bitmask comparison to \textbf{select} a viable Level-$k$ child. When $\mathcal{A}$ \textbf{aligns} with a power of 2, this lookup and steering operation \textbf{consumes} a single table lookup [6].
        \item The resolution operation \textbf{descends} to the level-$k$ $\mathcal{L}$ identified by the steering vector from the Oracle.
        \item The resulting recurrence relation is:
        \begin{equation}
            T(\mathcal{L}_{k+1}) = I_{base} + T(\mathcal{L}_k) = I_{base} + kI_{base} = (k+1)I_{base}
        \end{equation}
        \item \textbf{Termination Constraint:} The recursion \textbf{terminates} at $\mathcal{L}_{1}$, where the hardware bit-scan \textbf{yields} the final effective address offset.
    \end{itemize}
\end{enumerate}


\subsection{Conclusion of Determinism}
By induction, the resolution time for any $n$-level $\mathcal{L}$ structure is strictly $nI_{base}$. While standard stochastic allocators exhibit execution times as a function of free-block count ($N$)—typically yielding $O(\log N)$ or worse in fragmented states [7]—the \textbf{Iscandar} architecture \textbf{collapses} this complexity. $n$ as a constant \textbf{enforces} deterministic latency of resolution regardless of heap saturation.\\

In our model, $n$ is an architectural constant (e.g., $n = 3$); so total execution time is:
\begin{equation}
    T_{total} = 3I_{base}
\end{equation}

This result confirms that for a Cube of $\mathcal{A}^k$ Sectors, the time required to resolve an address is invariant. This performance is maintained provided the system stays in the operational domain of the Occupancy Limit ($\Phi$). By trading spatial capacity for temporal certainty, the architecture \textbf{eliminates} the ``temporal jitter'' that characterizes non-deterministic real-time systems. [8]

\subsection{Temporal Consistency and Boundary Management}
To \textbf{preclude} latency variability during boundary-straddling, \textbf{Iscandar} \textbf{utilizes} a computational handshake or ``Oracle,'' a precomputed resolution-path for non-aligned straddle cases, \textbf{ensuring} the instruction count for a $\mathcal{A}$-sector block remains \textbf{isochronous} regardless of its alignment relative to the Tier-1 registers. By \textbf{eliminating} the alignment-check penalty, the architecture \textbf{preserves} a deterministic execution window across the entire addressable space.\\

Here we describe the ``Factory'' math used to pre-calculate the Oracle tables, transforming a search problem into a static retrieval of pre-verified geometric facts.

\subsubsection{Generating the Left and Right Hand Lookup Oracle}
Part of the Oracle are tables of 1D vectors that map every possible bit-permutation of a Guard Shard to its boundary potential.   These are pre-calculated \textit{Finite State Automata} that eliminate runtime scanning functioning as a direct mapping of the manifold’s geometry onto the Look-Up Tables (LUTs) of the Phase IV hardware.
\begin{itemize}
    \item \textbf{Right-Hand Lookahead (RHL):} For any shard state $S$, the table stores the starting index of the longest contiguous zero-run terminating at the right-hand boundary. If the terminal bit is \textbf{1}, the value is \textbf{Null}.
    \item \textbf{Left-Hand Lookahead (LHL):} Maps the shard state to the final bit position of the zero-run starting from the left-hand boundary. If the initial bit is \textbf{1}, the value is \textbf{Null}.
    \end{itemize}

\subsubsection{Generating the Center Oracle (2D Matrix)}
The Core Shard utilizes a 2D matrix ($2^{\mathcal{A}/4} \times \mathcal{A}/4$) to resolve internal gaps.
\begin{itemize}
    \item \textbf{Mechanism:} Exhaustive enumeration of all $2^{\mathcal{A}/4}$ bit-patterns against all possible length requests within the core.
    \item \textbf{Math:} Each cell $(i, j)$ is filled using a windowed zero-run algorithm. This transforms the shard into a precalculated \textit{Finite State Automata}, where the resultant state-space is compressed into the Phase IV hardware’s static lookup tables for single-cycle gap resolution.
\end{itemize}

\section{Deterministic Coalescence and the Occupancy Limit}
Maintaining temporal determinism in a dynamic environment \textbf{requires} a deallocation process (coalescence) \textbf{mirroring} the efficiency of the allocation logic. Operational stability of the \textbf{Iscandar} lattice uses discrete enforcement of the Occupancy Limit($\Phi$), \textbf{precluding} the high-entropy states typically associated with conventional allocators [9].

\subsection{Symmetric Coalescence Mechanics}
Here, coalescence is not a variable-time search for adjacent free blocks, but a deterministic state update. Whether the Oracle descends to clear a bit-position or propagates the release upward through the hierarchy, the operation remains isochronous. Because the bit-address of any Sector ($S_0$) is a fixed function of its coordinates, the update to the occupancy counters ($\Gamma$) consumes the same instruction count ($I_{base}$) as the initial resolution. \textbf{The alignment is self-similar across all hierarchical depths, a property derived from the Structural Arity ($\mathcal{A}$) rather than a pre-defined set of size-classes.}

\begin{enumerate}
    \item The atomic leaf node state $\Gamma_0$ is toggled to 0 (Available).
    \item The change propagates immediately to the parent Row counter ($\Gamma_1$).
    \item The Level-2 (Plane) and Level-3 (Cube) counters are updated through integer subtraction.
\end{enumerate}

Because the lattice depth is fixed at $n = 3$, time complexity for allocation is identical to deallocation ($3I_{base}$). This symmetry ensures that system overhead remains constant regardless of memory ``churn,'' eliminating the temporal spikes typically made by coalescing algorithms. [10]

\subsection{Operational Enforcement of $\Omega$}
The Occupancy Limit ($\Phi$) \textbf{serves} as the authoritative boundary of the system’s operational domain. While traditional allocators attempt to satisfy requests until the address space is 100\% utilized---leading to $O(N)$ search patterns as fragmentation increases [11]---our  lattice uses the $\Gamma_{3}$ counter as a deterministic ``circuit breaker,'' depending on the memory request of the moment.\\

The decision logic for the Resolution Operator ($\Omega$) is:
\begin{equation}
\Omega(\text{request}) = 
\begin{cases} 
\text{Resolve}(p, r, s) & \text{if } \Gamma_{3} < K \\
\text{Refuse}(\text{Constant Time}) & \text{if } \Gamma_{3} \geq K 
\end{cases}
\end{equation}
where $K$ is the sector threshold at which the Occupancy Limit is triggered ($K = \mathcal{A}^k \times (1 - \Phi)$)

\subsection{Summary of Empirical Performance}

This enforcement mechanism ensures the system never enters the ``fragmentation trap.'' By refusing to allocate beyond the occupancy limit ($\Phi$), \textbf{Iscandar} guarantees that the internal density of the $\mathcal{A}$-way branching structures never reaches a threshold where bit-mask steering degrades to a linear probe. This confirms a \textbf{flat temporal profile} until the moment of refusal.

Let $\Gamma_{total}$ be the sum of all leaf nodes $S_{0,i}$. At any discrete time $t$, the hierarchical counters \textbf{must} satisfy the invariant:

\begin{equation}
    \Gamma_{Apex} \text{ (a.k.a. } \Gamma_{3}) = \sum \Gamma_{2} = \sum \Gamma_{1} = \sum \Gamma_{0}

\section{Observations}

Earlier sections established \textbf{Iscandar} as deterministic within the primary scope of this paper. However, it exhibits properties warranting distinct architectural observations.

\subsection{As an Extension to Binary Buddy Systems}
The binary buddy system, pioneered by Knowlton [12] and Knuth [13], sought to minimize search latency through a power-of-two partitioning scheme ($R=2$). While this approach facilitates efficient coalescence, its search complexity remains fundamentally constrained to $O(\log_{2} n)$. As modern memory address spaces scale alongside processor word sizes, the increasing logarithmic depth of these trees drives significant latency. Furthermore, at high utilization, binary buddy systems trigger ``stalling'' behaviors; the search algorithm must traverse increasingly fragmented leaf nodes, which inevitably erodes deterministic performance.\\

We generalize buddy system principles to an \textbf{Arbitrary Radix} ($R=\mathcal{A}$). By shifting from a binary tree to a high-radix fractal lattice, we collapse the depth of the search space to a fixed architectural constant $n$. This structural shift moves memory management from the domain of probabilistic searching to the domain of \textbf{Geometric Coordinate Resolution}.

\subsection{As a Symmetric Voronoi Partition}
As detailed in the Architectural Axioms (Section 2.1), this lattice functions as a \textbf{Symmetric Voronoi Partition}, where the adjacency of ``buddies'' is a pre-baked geometric property of the address space rather than a calculated proximity, as shown in Section 5.2.\\ 

In this model, adjacency is defined by a partition's total volume \textbf{associating} with its handle (a wrapped pointer resolved in Section 9.4) rather than the Euclidean distance of individual points from a centroid. rather than the Euclidean distance of individual points from a centroid, as established in the geometric rules of the address space.\\

In a standard Voronoi partition, boundaries are dynamically computed as a function of the Euclidean distance to a specific ``seed'' or generator point. In the Iscandar lattice, while the ``seed'' is represented by the wrapped pointer, the partition boundaries are not computed at runtime, as defined by the invariant geometric properties of the lattice established in the Observations section. Instead, they are architecturally invariant, defined strictly by the Structural Arity ($\mathcal{A}$) and the hierarchical depth ($k$) established in the Axioms. This replaces the need for distance-based calculations with a pre-baked, static coordinate resolution:

\begin{equation}
\text{Boundary}_{\text{Iscandar}} = f(\mathcal{A}, k) \neq f(\text{dist}(p, \text{seed}))
\end{equation}

\subsection{As Linear Programming}

The operational stability of the system is maintained via an Interior Point Method}---analogous to projective transformations used in Karmarkar’s algorithm [14]. By enforcing a \textbf Occupancy Limit ($\Phi$), we \textbf{ensure} the resolution path avoids ``edges'' of the feasible region (the fragmentation trap). Here, the allocator does not merely manage space; it \textbf{navigates} a high-dimensional manifold where the floor serves as a protective barrier against non-deterministic search behaviors.

\subsection{Amortized Performance: Constant Time}
The \textbf{Iscandar} architecture utilizes a \textit{Seamless Sack} model that achieves amortized constant time for memory operations through a Next-Fit Circular Cursor mechanism.

\begin{itemize}
    \item \textbf{Mechanism:} The cursor maintains forward momentum across the $\mathcal{A}^k$-sector manifold. By never re-scanning fragmented entropy within a single ``lap,'' the system distributes the metabolic cost of search across its entire operational lifecycle.
    \item \textbf{Principle:} The system offsets the latency of filtering fragmented sectors by performing high-efficiency, contiguous allocations in reclaimed or vacant regions.
\end{itemize}

\subsection{Worst Case Performance: Sub-Linear Time}
The architecture maintains determinism through hierarchical skip-logic at intermediate levels. This mechanism constrains the worst-case search complexity to the $k$-th root of the total lattice volume, where $k$ represents the depth of the fractal hierarchy.

\begin{itemize}
    \item \textbf{Mechanism: Dimensional Collapse.} The architecture maps the 1D address space to a $k$-dimensional manifold ($\mathcal{A}^k$). Metadata sentinels at the Plane and Row levels enable the search engine to bypass saturated volumes without bit-level interrogation.
    \item \textbf{Logic for the Geometry:}
    \begin{enumerate}
        \item \textbf{Plane-Skip:} Evaluates $\mathcal{A}^2$-sector planes; skipping when free space is less than request.
        \item \textbf{Row-Skip:} Evaluates $\mathcal{A}$-sector rows; skipping when row density proves prohibitive.
        \item \textbf{Bit-Scan:} The engine restricts final verification to a single bit-vector of magnitude $\mathcal{A}$.
    \end{enumerate}
    \item \textbf{Ceiling:} For a lattice of volume $N = \mathcal{A}^k$, the architecture caps the maximum investigation path at $k \times \mathcal{A}$, limiting the worst-case cost to $k \times \mathcal{A}$ operations.
\end{itemize}

\section{Glossary of Terms}

\begin{description}
    \item[Atomic Polytope] The leaf-level search polytope within a Row manifold (Level 0). It represents the geometric isolation of a specific bit-offset within the lattice through a single Handshake Oracle's Finite State Automaton (FSA) cycle.
    
    \item[Coefficient of Variation (CV)] A statistical measure of the dispersion of data points. In the \textbf{Iscandar} context, having a CV of zero would in theory confirm that the instruction path length is identical across all execution cycles. [15]

    \item[Isochronous] The property of an algorithm to execute each time in the same amount of time regardless of input or current state, within a permissible variance. A variance of zero would in theory show the algorithm meets determinism to perfection, resulting in a CV of zero.
    
    \item[Contiguity Guarantee] The formal assurance (Section 2.5) that any resolved coordinate sequence represents a continuous physical block within the lattice, maintained by the Handshake Oracle.
    
    \item[Global Registrar] The Level 3 (Cube Scale) apex of the hierarchy. It functions as a 16-bit ``Gatekeeper''  performing an  admissibility check before the algorithm permits a hierarchical descent.
    
    \item[Handshake Oracle (LHL/RHL/Center)] "Oracle" for short, a Finite State Automaton, being a precomputed body of solutions used at the Tiny (Level 0) and Small (Level 1) allocator levels to bridge ``fractured'' sequences between sectors. It uses Left-Hand Lookahead (LHL), Right-Hand Lookahead (RHL) and Center Lookahead tables to weld adjacent fragments into a contiguous magnitude. In microcontroller implementations these are laid out as ROM tables. 
    
    \item[Polytope Formation] The visual representation of the admissible search space within the lattice. Each hierarchical tier (Cube, Plane, Row) can manifest polytopes that collapse as memory occupancy increases.
    
    \item[Occupancy Limit ($\Phi$)] The mandatory occupancy boundary (Section 4.2) that prevents the system from entering a high-entropy state. Once the floor is reached, the system issues a deterministic refusal rather than engaging in variable-time search.
\end{description}

\section{Description of Instruction Groups}

We map each instruction group to a specific predicate of the \textbf{Iscandar} hierarchy established in the Architectural Axioms. This ensures the hardware execution is a transparent reflection of the underlying mathematics. Here, we assume a 32-radix descent where each level acts as a ``Gate'' that must be cleared to reach the subsequent tier.

\subsection{Phase I: The Admissibility Gate (Level 3)}

\vspace{12pt}
\setcounter{equation}{14}
\noindent \textbf{Predicate:} 
\begin{equation}
    L \in \Gamma_{Apex} \iff \Gamma_{Apex} \leftarrow \Gamma_{Apex} + L
    \label{eq:predicate_apex}
\end{equation}
\vspace{12pt}

\begin{enumerate}
    \item \textbf{Instruction Group 1:} Load Global Registrar: Fetch the 16-bit register located at the Apex sector address as defined in the Cube Scale Allocator.
    \item \textbf{Instruction Group 2:} Admissibility Comparison: Compare against the requested magnitude $L$. If False: Immediate Exit (Fast-Fail) as required by the Global Registrar's heuristics. If True: Increment by the requested magnitude.
\end{enumerate}

\subsection{Phase II: The Plane-Level Resolution (Level 2)}

\vspace{12pt}
\setcounter{equation}{15}
\noindent \textbf{Predicate:} 
\begin{equation}
    P_{Plane} \iff \sum_{i \in Plane} (Row [Inclusion]) \ge L
    \label{eq:predicate_plane}
\end{equation}
\vspace{12pt}

\begin{enumerate}
    \setcounter{enumi}{2}
    \item \textbf{Instruction Group 3:} Index Plane Metadata: Using the address bits, index into the 32-radix plane metadata table.
    \item \textbf{Instruction Group 4:} Load Row-Summary: Fetch the 15-bit metadata for the target plane summarizing the 32 constituent rows as established in Axiom II.
    \item \textbf{Instruction Group 5:} Candidate Selection: Evaluate the plane-state to identify the first row-sequence that satisfies the weld.
    \item \textbf{Instruction Group 6:} Heuristic Branch/Scan: Evaluate the 32-radix plane metadata scan to confirm the steering vector.
\end{enumerate}

\subsection{Phase III: The Row-Level Weld (Level 1)}

\vspace{12pt}
\setcounter{equation}{16}
\noindent \textbf{Predicate:} 
\begin{equation}
    Weld \iff RHL(Row_n) + Intermediates + LHL(Row_{n+m}) \ge L
    \label{eq:predicate_weld}
\end{equation}
\vspace{12pt}

\begin{enumerate}
    \setcounter{enumi}{6}
    \item \textbf{Instruction Group 7:} Leading Fragment Access (RHL): Perform a Look-Up Table (LUT) lookup on the starting row's tail.
    \item \textbf{Instruction Group 8:} Trailing Fragment Access (LHL): Perform a LUT lookup on the final row's head.
    \item \textbf{Instruction Group 9:} Scalar Summation: Add Lead + Intermediates + Trail, maintaining the Contiguity Guarantee.
    \item \textbf{Instruction Group 10:} Weld Validation: Compare the result against $M$ to finalize the inter-row continuity.
\end{enumerate}

\subsection{Phase IV: The Bit-Lattice Isolation (Level 0)}

\vspace{12pt}
\setcounter{equation}{17}
\noindent \textbf{Predicate:} 
\begin{equation}
    P_{Tiny} \iff \sum_{i=start}^{end} \neg b_i = L
    \label{eq:predicate_tiny}
\end{equation}
\vspace{12pt}

\begin{enumerate}
    \setcounter{enumi}{10}
    \item \textbf{Instruction Group 11:} Center LUT Index: Access the bit-occupancy table for the target sector.
    \item \textbf{Instruction Group 12:} Triangle Projection: Map the LUT result to the physical bit-offset, resolving the Atomic Polytope within the Row manifold.
    \item \textbf{Instruction Group 13:} Commitment/Return: Write the new occupancy to the 15-bit metadata and return the start address $S$.
\end{enumerate}

\section{Desk Check Summary: The Tiny Search ($L \le 8$)}

Here we posit a hypothetical 32-bit machine providing the data structures needed to demonstrate one example through the Instruction Groups, on possible "Tiny Search" tracing  the sequence needed to resolve an allocation request $L$ of 8 sectors or fewer.

\begin{enumerate}
    \item \textbf{Admissibility Check:} The Global Registrar compares the request size $L$ against the aggregate occupancy ($\Gamma$) and entropy thresholds.
    \item \textbf{Plane Navigation:} The Rotational Steering Vector ($\vec{R}$) is applied at the Cube level to select a candidate Plane.
    \item \textbf{Metadata Retrieval:} The 32-bit Row-Summary mask for the selected plane is loaded into the register.
    \item \textbf{Row Isolation:} A mask check identifies the first available Row index within the plane summary.
    \item \textbf{Sector Load:} The 32-bit data word representing the candidate Row is fetched.
    \item \textbf{Hierarchical Bisection:} The 32-bit row is divided into two 16-bit "Half-Words" to initiate the Oracle probe.
    \item \textbf{Oracle (High):} A LUT probe returns the Right Hand Lookahead for high 16 bits.
    \item \textbf{Oracle (Low):} A LUT probe returns the Left Hand Lookahead for low 16 bits.
    \item \textbf{Boundary Intersection:} The system calculates the "Center-Straddle" by summing the RHL of the high half and the LHL of the low half.
    \item \textbf{Core Shard Interrogation:} If the straddle fails, the 32-bit row is treated as four 8-bit quadrants for unrolled sequential validation.
    \item \textbf{Geometric Resolution:} The successful bit-run is mapped to a physical offset using the Triangle Projection method.
    \item \textbf{Lattice Commitment:} The new occupancy state is masked into the row, and local metadata is updated.
    \item \textbf{Deterministic Exit:} The system returns the resolved pointer.
\end{enumerate}

\section{\textbf{Iscandar}: Laboratory Source Code}

This DYALOG APL implementation was used to generate the report's tables. The test code simulates high-churn volumetric stress to verify determinism of the sentinel-steered geometry.

\begin{lstlisting}[caption={ISCANDAR 16.4.1 Lab Implementation}, label={lst:Iscandar_code}]
⍝ ==============================================================================
⍝ Iscandar ARCHIVE 
⍝ AUTHORED BY: ANDREW JONATHAN FINE
⍝ PURPOSE: DETERMINISM VIA RADIX-32 SENTINEL STEERING
⍝ ==============================================================================
⎕IO ← 1

⍝ --- MODULE 1: ARCHITECTURAL CONSTANTS ---
A ← 32 ⋄ K ← 3 ⋄ V ← A*K

⍝ --- MODULE 2: MANIFOLD INITIALIZATION ---
∇ INIT_GEOMETRY
  LATTICE ← (V⍴0)      
  PMASK ← (A⍴0)        
  RMASK ← (1024⍴0)     
  SCAN_OVERHEAD ← 0    
  ⎕ ← 'ISCANDAR: ARCHIVE MASTER ONLINE (V=32768)'
∇

⍝ --- MODULE 3: THE ISCANDAR ORACLE (ALLOCATION) ---
∇ Z ← ALLOC_K13 Size;p;r;found;row_start;r_idx;rows_needed;check_range
  SCAN_OVERHEAD ← 0 ⋄ found ← 0 ⋄ Z ← 0
  rows_needed ← ⌈Size ÷ A
  :For p :In ⍳A
    SCAN_OVERHEAD +← 1 ⍝ Plane Gate Tax (Macro G03)
    :If PMASK[p] = 0
      :For r :In ⍳A
        r_idx ← ((p-1)×A)+r
        SCAN_OVERHEAD +← 1 ⍝ Row Gate Tax (Macro G05)
        :If (r_idx + rows_needed - 1) ≤ 1024
          check_range ← RMASK[r_idx + ⍳rows_needed - 1]
          SCAN_OVERHEAD +← ⍴check_range 
          :If ∧/ check_range = 0
            row_start ← ((r_idx-1)×A) + 1
            LATTICE[row_start + ⍳Size - 1] ← 1 ⍝ Atomic Write (G08)
            SCAN_OVERHEAD +← 1 
            RMASK ← ∨/ (1024 32 ⍴ LATTICE)
            PMASK ← ∨/ (32 32 ⍴ RMASK)
            Z ← row_start Size ⋄ found ← 1 ⋄ :Leave
          :EndIf
        :EndIf
      :EndFor
    :EndIf
    :If found ⋄ :Leave ⋄ :EndIf
  :EndFor
∇

⍝ --- MODULE 4: ENTROPY REVERSAL (DEALLOCATION) ---
∇ FREE_K13 Data;idx;sz
  :If 0 = ⍴,Data ⋄ :Return ⋄ :EndIf
  (idx sz) ← ,Data
  LATTICE[idx + ⍳sz - 1] ← 0
  RMASK ← ∨/ (1024 32 ⍴ LATTICE)
  PMASK ← ∨/ (32 32 ⍴ RMASK)
∇

⍝ --- MODULE 5: STATISTICAL AUDIT HARNESS ---
∇ RUN_LAB;SACK;sz;res;history;occ;c;stats;t;m;s;idx;v
  INIT_GEOMETRY ⋄ SACK ← ⍬ ⋄ history ← 0 3⍴0 ⋄ occ ← 0
  :For c :In ⍳500
      sz ← 1 + (?1024) + (0 = ?10) × ?14000 
      res ← ALLOC_K13 sz
      :If res ≢ 0
          history ← history ⍪ occ sz SCAN_OVERHEAD
          SACK ,← ⊂res ⋄ occ +← sz
      :EndIf
      :If (0 = 5 | c) ∧ (⍴SACK) > 0
          idx ← ?⍴SACK ⋄ FREE_K13 ⊃SACK[idx]
          occ -← (⊃SACK[idx])[2] ⋄ SACK ← ((⍳⍴SACK) ≠ idx) / SACK
      :EndIf
  :EndFor
  ⎕ ← ' Usage (Sect) | Request | Touches ' 
  ⎕ ← (-50 ⌊ 1↑⍴history) ↑ history
  t ← history[;3] ⋄ m ← (+/t)÷(⍴t)⌈1 
  s ← (((+/(t-m)*2)÷(⍴t)⌈1)*0.5) ⋄ v ← s*2
  ⎕ ← '--- AUDIT COMPLETE ---'
  ⎕ ← 'MEAN OVERHEAD (METABOLIC COST): ',⍕m 
  ⎕ ← 'SIGMA (JITTER): ',⍕s ⋄ ⎕ ← 'VARIANCE: ',⍕v
∇
\end{lstlisting}
